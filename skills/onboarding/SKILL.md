# Onboarding — get users to the aha moment

Most users decide in the first minutes. A great product with bad onboarding
looks like a bad product. This stage engineers the path to first value.

## Connected skills
- Reads:    `## 01 Idea`, `## 04 Design`, `## 12 Sales`, `## 13 Support`
- Writes:   `### Onboarding` (under Quality & Discovery), updates `## 04 Design`
- Agents:   `ux-designer`, `copywriter`
- Previous: `design` / `build`
- Next:     back to the flow (refine in `operate`)

## Goal
A first-run experience that reliably and quickly delivers the core value to a new
user, with an activation metric to track it.

## Inputs
- The core job (`## 01 Idea`), the critical flow (`## 04 Design`), and any
  drop-off data (`## 12 Sales` / analytics).

## Before you start
Check that `## 01 Idea`, `## 04 Design`, `## 12 Sales`, `## 13 Support` are filled in COMPANY.md. If a section you depend on is empty or still `_TBD_`, stop and tell the founder which skill fills it (see the orchestrator's stage table) instead of guessing.

## Process
1. **Define the aha moment.** The first instant a user feels the value (e.g.
   "received their first digest"). Make it concrete and measurable.
2. **Find the shortest path to it** with `ux-designer`. Count every step from
   signup to aha. Cut, defer, or automate each one.
3. **Reduce setup friction.** Sensible defaults, prefilled data, sample/demo
   content so an empty account still shows value. Don't make users build before
   they benefit.
4. **Guide, don't dump.** Progressive disclosure, a focused first task, empty
   states that teach. With `copywriter`, write microcopy that orients in a glance.
5. **Set the activation metric.** Define "activated" (reached aha within X) and
   instrument it.
6. **Watch real users** (tie into `research`) and remove the step where they
   stall.

## Exit criteria
- A defined, measurable aha moment.
- The path to it is as short as it can be, with helpful empty/first states.
- An activation metric instrumented.
- Evidence shown for each criterion above (command output, screenshot, link, or measurement), not just asserted.
